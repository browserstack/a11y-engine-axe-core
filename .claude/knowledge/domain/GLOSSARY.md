# Glossary

Spectra-specific terminology. When code and docs conflict, **code wins**.

## Run

One end-to-end run of the engine for a single page. Has a `scanId` (also called `runId` downstream). Lifecycle: extension `scan_started` → DOM chunks → B1/B2/C/AI lanes → consolidation → `sendResponse` to WebA11y.

## Scan

Contains multiple runs. Runs can be full page or mutation. Mutations are only for Workflow Analyser.

## scanId / runId

The same identifier viewed from two layers. `scanId` is what the extension and WebA11y use; `runId` is the downstream form, derived from `payload.configuration.metadata.productMetadata.scanRunId` or `payload.uuid` in the socket `scan_started` handler.

## Scope key

`product@userId@scanId` — the unit of result aggregation, which is like a UUID for a scan. Built by `getScopeKey()` in `ip-protection/utils/helpers.js`. Used in completion-tracking Redis keys like `scanComplete:${scopeKey}:${type}`.

## Type A / B1 / B2 / C / AI

The five rule lanes. **Worker-based**, not JSON-location-based. See `knowledge/docs/flows/rule-types.md` for the full table.

## Proxy map

Map of original asset URL → S3-hosted proxy URL. Built by `worker/proxyMapWorker.js:generateProxyMap`. Required for Type C rules to render in Percy without phoning home — Percy uses the map to route every asset request through S3.

## Combined rules

The B1/B2 rule batch runner. The class chain `combined-rules-class-v1` → `combined-rules-class-v14` (and counting) implements append-only versioning so in-flight scans on older versions keep working. See `knowledge/docs/flows/versioning.md`.

## EOF

End-of-file marker in Redis. Signals a chunked payload is complete and ready for a worker to dispatch. Used by `b1DataChunkHandler` to know when accumulated B1 DOM data is complete, and by Custom Elements AI / Heading AI for their own chunked streams.

## kill switch

Two distinct things:

- **Rules cache + kill-switch cache** — initialized at server startup via `refreshAllKillSwitchCaches()`. Stores per-customer rule disablements.
- **`isKillSwitchActive(userId, groupId, scanId)`** — used in `controllers/buildProxyMap.js`. When true, marks **all six** `COMPLETION_TASK_TYPES.*` as already-done and returns 200 immediately, no Percy call.

## `COMPLETION_TASK_TYPES.*`

Six markers in `ip-protection/config/enum.js`:

- `TYPE_C`
- `TEXT_IN_IMAGES`
- `AI_STANDARD`
- `AI_COLOR_CONTRAST`
- `AI_HTML`
- `AI_CUSTOM_ELEMENTS`

Each is marked complete via `markTaskCompleted(...)` before `sendResponse(...)` at every exit point. Consolidation waits on all of them.

## `dummySelector`

Placeholder string in Type C rule JSON (`"selector": "dummySelector"`). The real selector is computed inside the runner on Percy. Don't evaluate the JSON's `selector` field literally for Type C rules.

## `ai_${runId}` vs `aihtml_${runId}`

The two Redis state keys for AI flows, **mutually exclusive per runId** by Lua-atomic check:

- `ai_${runId}` — Type C-originated AI (alt-text, color-contrast, custom-elements). Created by `createAIrunIdMapping` in `controllers/getProxyMap.js:processProxyMapRequest` **before Percy is invoked**, if `rules[]` contains an applicable AI rule.
- `aihtml_${runId}` — B1-originated heading AI. Created by `setAIHtmlMetadataIfAIKeyEmpty` in `utils/redis-utils.js` via Lua script that sets only if `ai_${runId}` is empty.

Both TTL'd at `REDIS_TTL = 2 h`.

## `scan_state:${runId}`

Redis key for the STARTED flag. Set by socket `scan_started` handler with `SCAN_STATE_TTL = 60 s`. Gates `processPendingStatuses` — if `notifyRunStatus` events arrive before `scan_started`, they queue at `scan_pending_status:${runId}` (60s TTL) and flush when `scan_state` is set.

## `b1_data:${scanId}@${uuid}`

Redis key for accumulated gzip-buffered DOM chunks from the extension. TTL `B1_REDIS_EXPIRY = 1 h`. Drained by `workerB1.js` on EOF.

## `resources:${scanId}`

Per-scan map of resource UUID → presence flag. Lets later uploads reuse already-staged assets. TTL 28800 s (8 h, inline in `proxyMapWorker.js`).

## EDS

BrowserStack's event data system (BigQuery-backed). The browser-side `EDSUtils.createEDSEvent(config)` in `a11y-engine-core/lib/core/utils/eds-utils.js` and the server-side `new EDSUtils(eventType, scanId)` in `ip-protection/utils/eds-utils.js` both emit there.

## Chitragupta

Internal log-correlation framework. `Chitragupta.setMetaData('userId', ...)` registers per-request metadata that subsequent `logger.log(...)` calls inherit. Wrapped in `ip-protection/utils/logger.js`.

## consolidatedRules.json

Build artifact in `a11y-engine-core/consolidated_rules.json`, regenerated by `a11y-engine-core/build/scripts/consolidate_rules.js`. Copied to the sibling `accessibility` repo at `accessibility/db/rules/a11y_engine_${VERSION}.json` during release. Tells WebA11y which rules ship in this engine version.

## WebA11y

Internal name for the BrowserStack Accessibility backend product. Lives in the sibling `accessibility` repo. Receives Spectra's consolidated scan response via `POST /api/a11y_engine_jobs`.

## ngrok (port 8881)

Used in dev to expose the local `ip-protection` server to Percy so AI webhooks and `/accept_percy_result` POSTs can reach the laptop. The setup script auto-launches the daemon.

## Vault

HashiCorp Vault, behind VPN. Stores Percy tokens, WebA11y API credentials, AI service credentials. `scripts/setup.sh` fetches them into `keys.yml`.

## `-AT` suffix

Semver pre-release marker for AT-only releases (Assisted Tests). Excluded from this stack's scope.
